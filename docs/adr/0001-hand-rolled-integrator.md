# 1. เขียน parser และตัวหาปริพันธ์เอง แทนการใช้ CAS สำเร็จรูป

วันที่: 2026-09-05

## สถานะ

ตกลงแล้ว

## บริบท

สื่อ `integrals/antiderivative-basics.html` ต้องมีช่องให้ผู้ใช้พิมพ์ `f(x)` แล้วระบบตอบ `∫f(x)dx`
พร้อมแสดงขั้นตอนว่าใช้สูตรไหนในตารางสูตรของหน้านั้น

ทางเลือกที่ชัดเจนที่สุดคือโหลด CAS สำเร็จรูป (nerdamer, Algebrite, math.js) จาก CDN
ซึ่งจะได้ความสามารถกว้างกว่ามากโดยแทบไม่ต้องเขียนโค้ดเอง

แต่ข้อกำหนดหลักของโปรเจกต์ (ดู CLAUDE.md) คือ **ทุกไฟล์ต้องเปิดด้วยดับเบิลคลิกผ่าน `file://`
แล้วทำงานได้ครบโดยไม่ต้องรันเซิร์ฟเวอร์และไม่ต้องต่อเน็ต** — เพราะครูฉายในห้องเรียนที่เน็ตอาจไม่มี
และเคยเจอบั๊กจริงมาแล้วว่าโปรแกรมแสดงผล HTML บางตัวโหลดไฟล์ภายนอกไม่สำเร็จ (เป็นเหตุผลเดียวกับที่
โปรเจกต์นี้ฝัง CSS ไว้ในไฟล์ทุกหน้าแทนที่จะแยกไฟล์)

การฝัง CAS ทั้งก้อนลงในไฟล์ (inline) ก็ไม่เป็นทางออก เพราะจะทำให้ไฟล์สื่อโตขึ้นหลายร้อย KB
และแก้ไขด้วยมือทีหลังแทบไม่ได้

## การตัดสินใจ

เขียน tokenizer + recursive-descent parser + ตัวหาปริพันธ์เองใน `<script>` ของไฟล์นั้น
ครอบคลุมเท่ากับ **ตารางสูตรปริพันธ์พื้นฐานที่แสดงอยู่บนหน้าเดียวกัน** บวกด้วย
ผลบวก/ผลต่าง คูณค่าคงที่ และอาร์กิวเมนต์ภายในที่เป็นเชิงเส้น (`ax+b`) เท่านั้น

อินพุตที่อยู่นอกขอบเขตนี้ (เช่น `x·sin x`, `1/(x²−4)`) ต้องขึ้นข้อความบอกอย่างชัดเจนว่ายังไม่รองรับ
พร้อมยกตัวอย่างสิ่งที่พิมพ์ได้ — ห้ามตอบผิดเงียบๆ เด็ดขาด

## ผลที่ตามมา

- ไฟล์ยังเปิดออฟไลน์ได้ และยังแก้ด้วยมือได้เหมือนสื่ออื่นทุกชิ้น
- ขอบเขตที่รองรับตรงกับตารางสูตรบนหน้าพอดี ซึ่งกลายเป็นข้อดีเชิงการสอน:
  นักเรียนพิมพ์ได้เฉพาะสิ่งที่บทเรียนนี้สอน
- **แลกมาด้วย**: ถ้าอยากได้ integration by parts หรือ u-substitution ทั่วไปในอนาคต
  ต้องเขียนเพิ่มเองทั้งหมด ไม่มีทางลัด — ถ้าถึงจุดนั้นควรทบทวน ADR นี้ใหม่
- ต้องมีเคสทดสอบว่าอินพุตนอกขอบเขตแจ้งเตือนจริง ไม่ใช่ตอบมั่ว
