# ตัดคลิปแนวตั้งสไตล์ฟอนต์ไวรัล

เป้าหมายคือส่งไฟล์ `.mp4` ที่พร้อมอัปโหลดกลับไปให้เจ้าของงานเลย ไม่ใช่ส่งคำแนะนำให้เขา
ไปกดเองใน CapCut สคริปต์ในโฟลเดอร์นี้ทำงานหนักให้แล้ว หน้าที่หลักคือ **อ่านคลิปให้เข้าใจ
ก่อนเขียนข้อความ** และ **ตรวจงานที่เรนเดอร์ออกมาด้วยตาจริงๆ ก่อนส่ง**

## ลำดับงาน

### 1. ติดตั้งเครื่องมือ (ครั้งเดียวต่อ session)

```bash
bash .claude/skills/clip-cut/scripts/setup.sh
```

ลง ffmpeg (ผ่าน `imageio-ffmpeg` ถ้าเครื่องไม่มี) กับฟอนต์ Kanit ทั้ง 6 น้ำหนัก
คอนเทนเนอร์ถูกล้างทุกครั้งที่เริ่ม session ใหม่ จึงต้องรันใหม่ทุกครั้ง

### 2. สำรวจคลิปก่อน — ห้ามข้าม

```bash
python3 .claude/skills/clip-cut/scripts/probe_clip.py raw.mov --outdir probe
```

ได้มา: ความยาว/ขนาด, วินาทีที่เอนด์การ์ด CapCut เริ่ม, ตารางเทียบเกณฑ์ตัดช่วงเงียบ
และ **contact sheet** — ภาพรวมทุกวินาทีของคลิปเรียงเป็นตาราง

**เปิด contact sheet ดูจริงๆ ทุกแผ่น** นี่คือวิธีเดียวที่จะรู้ว่าคลิปเล่าอะไร ตอนไหน
ถ้าเนื้อหาสำคัญอยู่ในโซนเล็กๆ (เช่นกระดานหรือสไลด์) ให้รันซ้ำโดยใส่ `--crop W:H:X:Y`
เจาะเฉพาะโซนนั้น จะอ่านตัวหนังสือในคลิปออก

จดไทม์ไลน์ไว้ว่านาทีไหนพูดเรื่องอะไร แล้วค่อยไปเขียนข้อความ

### 3. เขียน config

สร้าง `clip.json` ข้างไฟล์วิดีโอ:

```json
{
  "source": "raw.mov",
  "output": "out.mp4",
  "end": 110.80,
  "min_silence": 0.90,
  "hook": {"start": 0.2, "end": 4.8,
           "line1": "แยกตัวประกอบ  x² + bx + c",
           "line2": "จับคู่เลข 2 ตัว จบใน 2 ขั้น"},
  "band": "แยกตัวประกอบพหุนามดีกรี 2",
  "pops": [
    {"start": 5.5,  "end": 12.5, "big": "x² + 6x + 5",  "small": "โจทย์ข้อ 1"},
    {"start": 75.0, "end": 87.0, "big": "คูณกันได้ -12  บวกกันได้ 1",
     "small": "ไล่ให้เจอคู่ที่", "layout": "WY"}
  ]
}
```

เวลาทั้งหมดเป็น **วินาทีบนคลิปต้นฉบับ** สคริปต์จะแปลงให้เองหลังตัดช่วงเงียบ

`end` เอาจากที่ `probe_clip.py` รายงานว่าจอดำเริ่ม — นั่นคือเอนด์การ์ด CapCut

### 4. เรนเดอร์

```bash
python3 .claude/skills/clip-cut/scripts/build_clip.py clip.json
```

### 5. ตรวจก่อนส่ง — ห้ามข้ามเช่นกัน

```bash
python3 .claude/skills/clip-cut/scripts/verify_clip.py out.mp4 --at 2 9 20 39 51
```

เช็คเสียงให้อัตโนมัติ (มีแทร็กไหม ดังพอทุกช่วงไหม ซ้าย/ขวาหักล้างกันไหม) แล้วดึงเฟรม
ตรงวินาทีที่ระบุออกมาเป็นภาพ **เปิดภาพดูทุกใบ** ว่า:

- ข้อความขึ้นตรงจังหวะกับสิ่งที่เกิดบนจอจริงไหม
- ตัวอักษรล้นขอบจอไหม (libass ไม่เตือน ต้องดูเอง)
- ข้อความไปบังอะไรที่ผู้ชมต้องอ่านหรือเปล่า

ระบุวินาทีให้ครอบคลุมทุกป้ายที่ใส่ไว้ อย่าสุ่มดูแค่สองสามจุด

## เรื่องที่พลาดกันบ่อย

**อย่าแต่งคำพูดขึ้นเอง** — ข้อความที่ใส่ต้องมาจากสิ่งที่ *เห็น* บนจอ (สมการที่เขียน
สไลด์ที่โชว์ ลำดับขั้นตอน) ไม่ใช่จากการเดาว่าเขาน่าจะพูดว่าอะไร ถ้าอยากได้ซับคำพูดจริงๆ
ให้ขอ **ไฟล์ SRT** จากเจ้าของงาน (CapCut มี "ถอดเสียงอัตโนมัติ" แล้ว export SRT ได้)
แล้วใส่ `"srt": "captions.srt"` ใน config

ในบางสภาพแวดล้อมนโยบายเน็ตเวิร์กบล็อก `huggingface.co` กับ `openaipublic.azureedge.net`
ทำให้โหลดโมเดล Whisper มาถอดเสียงเองไม่ได้ ถ้าเจอ 403 อย่าพยายามเลี่ยง — บอกตรงๆ
แล้วขอ SRT แทน และส่งงานส่วนที่ทำได้ไปก่อน

**อย่าตัดช่วงเงียบแรงเกินไปกับคลิปสอน** เกณฑ์ 0.4 วิที่ใช้กับคลิปพูดหน้ากล้อง พอเอามาใช้
กับคลิปที่บันทึกจอตอนเขียนกระดาน จะเกิดรอยตัด 40+ จุด ลายมือจะกระโดดจนดูไม่รู้เรื่อง
เพราะช่วงเงียบของครูคือช่วงที่กำลังเขียน ซึ่งเป็นเนื้อหาเอง ไม่ใช่ช่วงว่าง

ดูตารางที่ `probe_clip.py` พิมพ์ออกมา แล้วเลือกเกณฑ์จากจำนวนรอยตัด ไม่ใช่จากตัวเลขวินาที
สำหรับคลิปสอน **0.9 วิ** มักได้รอยตัดราว 10 จุด ซึ่งกำลังดี ถ้าเจ้าของงานสั่งเกณฑ์มาแล้ว
มันแรงเกินไปสำหรับคลิปนั้น ให้ทำเวอร์ชันที่พอดีก่อน **แล้วบอกเขาตรงๆ ว่าเบี่ยงจากที่สั่ง
เพราะอะไร พร้อมเสนอเวอร์ชันตามที่สั่งให้เลือก** — อย่าเงียบแล้วทำตามตัวเลขจนงานเสีย

**อย่าให้ป้ายซ้ำความหมายกันติดๆ** ก่อนเรนเดอร์ อ่านลิสต์ `pops` รวดเดียวเหมือนอ่านสคริปต์
ถ้ามีสองป้ายห่างกันไม่กี่วิแล้วพูดเรื่องเดียวกัน ให้รวมเป็นป้ายเดียวที่ค้างยาวขึ้น
หรือเปลี่ยนเนื้อหาป้ายหนึ่งไปเลย

**เสียงเงียบมักไม่ใช่ที่ไฟล์** ถ้าเจ้าของงานบอกว่าไม่ได้ยินเสียง ให้รัน `verify_clip.py`
พิสูจน์ก่อนว่าไฟล์มีเสียงจริง แล้วค่อยชี้ไปที่ตัวเล่น — การ์ดพรีวิววิดีโอในแอปแชท
ส่วนใหญ่เล่นแบบปิดเสียงอัตโนมัติ วิธียืนยันที่เร็วที่สุดคือดึงเสียงออกมาเป็น mp3
ส่งให้เขาลองเปิด

**ไฟล์วิดีโอไม่ commit ลง repo** repo นี้เก็บสื่อการสอน HTML ส่งไฟล์ที่เรนเดอร์เสร็จ
ให้เจ้าของงานโดยตรง เก็บไฟล์ชั่วคราวไว้ใน scratchpad

## รอบแก้

เก็บ `clip.json` ไว้ พอเจ้าของงานขอแก้ข้อความ ให้แก้ในนั้นแล้วเรนเดอร์ใหม่ทั้งไฟล์ —
เร็วกว่ามาไล่แก้ `.ass` และไม่พลาดเรื่องเวลาที่ต้องแปลงตามการตัดช่วงเงียบ
ตั้งชื่อไฟล์ออก `_v2`, `_v3` ไล่ไป เจ้าของงานจะได้เทียบเวอร์ชันเก่าได้

ถ้าอยากปรับสี ตำแหน่ง ขนาดฟอนต์ หรือสงสัยที่มาของค่าพวกนี้ อ่าน
`references/style.md` ก่อนแก้
