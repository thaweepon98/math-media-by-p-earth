# 4. เก็บเศษส่วนในข้อมูลเป็นข้อความ `a/b` แล้วแปลงเป็นบน/ล่างตอนแสดงผล

วันที่: 2026-09-07

## สถานะ

ตกลงแล้ว

## บริบท

`CONTEXT.md` กำหนดว่าเศษส่วนทุกจุดในสื่อต้องเป็นแบบบน/ล่าง (class `.frac`) และสแลชแนวนอนถือว่าไม่ได้มาตรฐาน

แต่ใน `math/fractions.html` เศษส่วนจำนวนมากไม่ได้อยู่ในมาร์กอัป — มันอยู่ใน **ข้อมูล**:

```js
{ q_th: '3/4 ÷ 1/2 = ?', opts: ['3/8','3/2','6/4','1 1/2'], ans: 3, exp_th: '3/4 × 2/1 = 6/4 = 3/2 = 1 1/2' }
```

และอยู่ใน **สตริงที่ JS ประกอบตอนรัน** (ขั้นตอนของเครื่องคิดเลข, ขั้นตอนเปรียบเทียบ) ซึ่งตัวเลขมาจากอินพุตผู้ใช้
เขียนล่วงหน้าเป็นมาร์กอัปไม่ได้

ทางเลือกที่พิจารณา:

1. **เขียน `frac()` ลงในข้อมูลตรงๆ** — `opts: [frac(3,8), frac(3,2), …]`, `exp_th: '3/4 × 2/1 = ' + frac(6,4) + …`
2. **เก็บ `"3/8"` ไว้เหมือนเดิม แล้วมีตัวแปลงตอนแสดงผล**

ทางเลือกที่ 1 ชัดเจนว่าอะไรเป็นเศษส่วน ไม่มีเวทมนตร์ แต่คลังข้อสอบจะเต็มไปด้วยมาร์กอัป
คนที่มาเพิ่มโจทย์ทีหลัง (คือครูเจ้าของสื่อเอง) ต้องจำได้ว่าห้ามพิมพ์สแลช — ซึ่งเป็นสิ่งที่พลาดง่ายที่สุด
และเป็นสาเหตุที่ไฟล์นี้มีสแลชค้าง 228 จุดตั้งแต่แรก

## การตัดสินใจ

เก็บเศษส่วนในข้อมูลเป็นข้อความ `a/b` (และจำนวนคละเป็น `w a/b`) ตามเดิม
แล้วให้ฟังก์ชัน `mathText(s)` แปลงเป็นมาร์กอัป `.frac` **ตอนแสดงผล** — เรียกเฉพาะจุดที่สตริงนั้นเป็นคณิตศาสตร์

`mathText` ตัดแท็ก HTML ออกก่อนแล้วค่อยแทนที่เฉพาะเนื้อความ จึงไม่ไปยุ่งกับ `<span style="…">` ที่ปนอยู่ในสตริง
และรับตัวเศษ/ส่วนที่เป็นวงเล็บได้ด้วย (`(2×3)/(3×4)`)

**การเรียกเป็นแบบ opt-in เสมอ ห้ามเรียกครอบทั้งหน้า** — เพราะ `CONTEXT.md` ระบุไว้ชัดว่าสแลชหลายแบบ
ไม่ใช่เศษส่วน โดยเฉพาะตัวนับลำดับที่อยู่ในไฟล์นี้เอง (`ข้อที่ 1 / 10`, `คะแนน 7 / 10`)

กันชนอีกชั้นคือ **สแลชต้องติดกับตัวเลขทั้งสองข้าง** ตัวแปลงถึงจะจับ — เศษส่วนเขียน `3/4` ส่วนตัวนับเขียน `1 / 10`
เว้นวรรคไว้ ทั้งสองแบบจึงแยกกันได้เองโดยไม่ต้องจำ ส่วนเนื้อหาคงที่ใน HTML ทำเครื่องหมายด้วย `class="mathy"`
แล้วให้ `applyMathText()` แปลงตอนโหลด (ใช้ได้เฉพาะบล็อกที่เป็นเนื้อหาคงที่ล้วน เพราะมันเขียนทับ innerHTML ทั้งบล็อก)

## ผลที่ตามมา

- เพิ่มโจทย์ใหม่ในคลังข้อสอบได้โดยพิมพ์ `5/8` ตามธรรมชาติ แล้วได้บน/ล่างอัตโนมัติ — มาตรฐานไม่หลุดเพราะคนลืม
- ข้อมูลยังอ่านออกและ diff ได้ ต่างจากการฝัง `<span class="frac">` ลงไป
- **แลกมาด้วย**: มีเวทมนตร์ที่มองไม่เห็นหนึ่งชั้น ถ้าวันหนึ่งมีโจทย์ที่ตั้งใจให้เห็นสแลชจริงๆ
  (เช่น สอนการพิมพ์สูตรลงเครื่องคิดเลข) ต้องเลี่ยงไม่เรียก `mathText` กับสตริงนั้น
- **แลกมาด้วย**: คนอ่านโค้ดจะเห็นสแลชในไฟล์ที่ประกาศว่าแบนสแลช — ADR ฉบับนี้มีไว้ตอบคำถามนั้น
- ถ้าเปลี่ยนใจไปทางเลือกที่ 1 ทีหลัง ต้องไล่แก้ทุกข้อในคลังข้อสอบและทุกสตริงของเครื่องคิดเลข จึงย้อนยากพอควร
- ตัวแปลงนี้อยู่ใน `fractions.html` ไฟล์เดียวก่อน ถ้าสื่ออื่นต้องใช้ค่อยคัดลอกไป (ทั้งเว็บใช้ CSS/JS ฝังในไฟล์อยู่แล้ว — ดู `CLAUDE.md`)
